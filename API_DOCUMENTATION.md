## 📦 1. Orders API
**Base Path:** `/api/orders`

Manage customer orders across different stores.

### `GET /api/orders`
* **Description:** Retrieves a paginated list of orders. Supports filtering by store or status.
* **Query Parameters:**
  * `storeId` (optional): Filter by specific store ID.
  * `status` (optional): Filter by order status.
  * `page` (optional): Page number (default: 1).
  * `limit` (optional): Number of records per page.
* **Returns:** Array of Order objects.

### `GET /api/orders/recent`
* **Description:** Retrieves the most recently placed orders (usually used for the dashboard feed).
* **Query Parameters:** `limit` (default: 10).
* **Returns:** Array of recent Order objects.

### `GET /api/orders/:id`
* **Description:** Retrieves the full details of a specific order by its ID.
* **Returns:** Single Order object.

### `POST /api/orders`
* **Description:** Creates a new order. Triggers a `order_created` WebSocket event.
* **Request Body:**
  ```json
  {
    "storeId": 1,
    "customer": "John Doe",
    "items": [{ "name": "Coffee", "price": 4.50, "quantity": 2 }],
    "totalAmount": 9.00,
    "notes": "Extra hot"
  }
  ```
* **Returns:** The created Order object (Status 201).

### `PATCH /api/orders/:id/status`
* **Description:** Updates the status of an existing order. Triggers a `order_updated` WebSocket event.
* **Request Body:**
  ```json
  {
    "status": "PREPARING" // PLACED, PREPARING, OUT_FOR_DELIVERY, COMPLETED, CANCELLED
  }
  ```
* **Returns:** The updated Order object.

## 🏬 2. Stores API
**Base Path:** `/api/stores`

Manage the different branch locations in the system.

### `GET /api/stores`
* **Description:** Retrieves a list of all stores.
* **Returns:** Array of Store objects.

### `GET /api/stores/:id`
* **Description:** Retrieves details for a specific store.
* **Returns:** Single Store object.

### `POST /api/stores`
* **Description:** Creates a new store location.
* **Request Body:**
  ```json
  {
    "name": "Downtown Branch",
    "location": "123 Main St",
    "status": "active"
  }
  ```
* **Returns:** The created Store object (Status 201).

### `PATCH /api/stores/:id`
* **Description:** Updates a store's details (name, location, or status).
* **Request Body:** Any subset of the store fields.
* **Returns:** The updated Store object.

### `DELETE /api/stores/:id`
* **Description:** Deletes a store from the system. *(Note: May fail if there are existing orders tied to this store due to foreign key constraints).*
* **Returns:** Success message (Status 200) or No Content (Status 204).

## 📊 3. Analytics API
**Base Path:** `/api/analytics`

Fetch aggregated data for dashboard visualizations and reporting.

### `GET /api/analytics/overview`
* **Description:** Returns high-level metrics (Total Revenue, Total Orders, Average Order Value).
* **Query Parameters:** `days` (optional, filters data to the last X days).
* **Returns:** Aggregated JSON statistics.

### `GET /api/analytics/orders-per-day`
* **Description:** Returns a chronological breakdown of order volume per day, formatted for line/bar charts.
* **Query Parameters:** `days` (optional, default 7).
* **Returns:** Array of `{ date, count, revenue }` objects.

### `GET /api/analytics/revenue-per-store`
* **Description:** Compares the total revenue generated by each store.
* **Returns:** Array of `{ storeName, totalRevenue }` objects.

### `GET /api/analytics/top-items`
* **Description:** Aggregates all JSON items across orders to find the best-selling products.
* **Returns:** Array of the top N selling items.

## 🗄️ 4. Archive API
**Base Path:** `/api`

Manage the archival process for old, completed orders to keep the main database table fast and lightweight.

### `POST /api/archive-old-orders`
* **Description:** Finds all orders older than a specified threshold with status `COMPLETED` or `CANCELLED`, moves them to the `orders_archive` table, and deletes them from the main `orders` table.
* **Request Body:** *(Usually empty, relies on backend date threshold logic).*
* **Returns:** Success message with the count of rows archived.

### `GET /api/archived-orders`
* **Description:** Retrieves a paginated list of historical/archived orders for auditing purposes.
* **Returns:** Array of OrderArchive objects.

## 🔌 WebSocket Events (Socket.IO)

In addition to HTTP endpoints, the backend emits real-time events that the frontend listens to.

* **`order_created`**: Emitted to all clients when a new order is successfully POSTed. Contains the new Order object.
* **`order_updated`**: Emitted to all clients when an order status is PATCHed. Contains the updated Order object.
